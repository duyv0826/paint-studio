## 二、改了什么

| # | 改动 | 为什么 |
|---|---|---|
| 1 | **三档条件**（温柔 / 标准 / 严厉）替代原来的「停笔多久算摸鱼」下拉 | 档位是自变量。阈值必须来自单一真源，界面显示的数字与判定用同一组数，否则条件不可复现 |
| 2 | **三路信号**：失焦、静默、笔速断崖；优先级 失焦 > 静默 > 断崖 | 原版只有「停笔」一路，且切走窗口完全不算；这三种摸鱼形态在测试里要分开记 |
| 3 | **提醒 → 恢复落笔延迟** `delay_ms` 自动记 | 原版要人工掐秒表；这是 D5 系统预计算指标 |
| 4 | **数据出口 JSON**（schema_version 2），缺标签拒收并列出缺项 | 防止无效数据混进研究样本；文件名自带编号/条件/轮次/任务 |
| 5 | **联机定向问号 + 摸鱼通知** | 录音 17 里「所有人都能发问号」那条；原版问号只是本机效果 |
| 6 | **每分钟落笔口径修正** | 原版分母是「页面打开到现在的时长」，被试先坐 5 分钟才点开始，落笔率就被摊薄。改成自习活跃时长 |
| 7 | **三个噪声源被掐掉** | 见第五节「冒烟查出的三个真问题」 |
| 8 | **版面**：数据条常驻画纸上方；左栏合并为一张卡；HUD 标签不再被挤成竖排 | 加两块后，1180×720 下「导出 JSON」原本掉到折叠线以外 |

## 三、条件与信号怎么判定

| 档位 | 静默 | 失焦 | 笔速断崖 | 冷却 |
|---|---|---|---|---|
| 温柔 | 60 s | 90 s | 跌到近 20 s 峰值 28%，持续 4 s | 45 s |
| 标准 | 20 s | 45 s | 跌到近 20 s 峰值 35%，持续 3 s | 30 s |
| 严厉 | 10 s | 20 s | 跌到近 20 s 峰值 50%，持续 2 s | 15 s |

判定口径（写进 Methodology 要能复述）：

- **断崖**只在「近 20 s 峰值 ≥ 300 px/s 且 3 s 内还有落笔」时判，避免把「停手」误判成断崖——停手归静默。
- **失焦**按「离开时长达到阈值、回到页面时」才提醒（离开期间人不在屏幕前，弹了也看不见）；这段离开时长记进该条记录的 `away_ms`。
- **一次提醒后要重新落笔才会再提醒**。人一直坐着不动，不会被每 15 秒弹一次。
- **人在窗口外时**，静默与断崖都不判定，交给失焦信号接管。

## 四、JSON 里有什么

```text
schema_version 2 · app · exported_at
session   participant_id / condition / condition_label / round / task /
          started_at / ended_at / active_sec / page_sec / planned_min / condition_switches[]
pomodoro  rounds_completed / focus_sec / today_strokes / today_undos
canvas    stroke_count / undo_count / strokes_on_canvas / path_len_px / draw_sec /
          avg_speed_px_s / peak_speed_px_s / session_sps / strokes_per_min
guard     level / enabled / thresholds{...} / reminder_count / reminders[{signal,at,delay_ms,away_ms,level}]
network   online / peers / nickname
data_valid / missing_fields[] / warnings[] / limits[]
```

- 缺 `participant_id / round / task` 任一项：**按钮直接拒绝导出**，界面上红色列出缺项，不产生文件。
- `data_valid` 由文件自己声明（标签齐 + 有落笔才为 true）；中途换档、零落笔会进 `warnings`。
- `limits[]` 写在数据里，谁拿到这份 JSON 都能看到它测不到什么。

## 五、验证记录（2026-11-13 20:05–20:15 实跑）

```
node --check 抽出的内联脚本      PASS（0 语法错误）
node smoke\smoke_v05.js          SMOKE_PASS 34/34（jsdom 真实 DOM）
Edge headless 1600×1000          目视：左栏全部内容在首屏，数据条与 HUD 不折行
Edge headless 1180×720           目视：档位/开关/问号/数据条/导出按钮全在首屏
```

冒烟覆盖：档位切换与阈值同源、缺标签拒收且不产生下载、落笔计数、静默 10 s 触发、恢复落笔解除警示、JSON 全字段、失焦 20 s 回页触发并记 `away_ms`、中途换档留痕、无运行期异常。

### 冒烟查出的三个真问题（已修，不是脚本问题）

1. **静默提醒会按冷却反复弹**：人一直不动，每 15 s 弹一次问号，既是噪音，也会把 `reminder_reactions` 灌满假记录 → 改为「提醒一次后需重新落笔才重新武装」。
2. **人在窗口外时还在算静默**：切走 30 s 会先弹一条「停笔」，回页再弹「失焦」，同一轮两条 → 改为离开期间静默/断崖不判定，由失焦接管。
3. **开测前设档被记成「中途换档」**：主试开测前选档属于准备动作，不该污染 `condition_switches` → 只有已开始自习或已有落笔才留痕。

## 六、没验的（不许当已完成）

1. **真实浏览器点击导出没跑过**：`导出 JSON / PNG` 的下载行为只在 jsdom 里用下载拦截断言过，没在真浏览器点一次落盘。**明天开测前请手点一次，确认 `Downloads` 里真的有文件。**
2. **双机联机未验证**：内嵌后端地址 `co-paint-studio.app.workbuddy.host` 在本机请求返回 403（可能是代理拦截），链路是否活着无法确认。现场看顶栏徽章：显示「联机 · n 人」才算通，否则自动单机，功能不减。
3. **断崖阈值是我拍的**：300 px/s 下限与 28/35/50% 比例没有拿真人笔速校准过，第一轮测试应当作观察项记录，别写进结论。
4. **监测范围仍只有本页画布**：录音 17 里说的「悬浮窗读 PS / Procreate」没有做，浏览器沙箱做不到；撤回步数也不是绘画软件的 Ctrl+Z。
