## 三、为什么要双路径播放

首次构建只走 WebAudio 的 `fetch → decodeAudioData`。实测发现 `file://` 下 `fetch` 被浏览器直接拦截（`TypeError: Failed to fetch`），双击打开时新音效会全哑。

改为：**优先 WebAudio**（低延迟、音量精确），`fetch` 失败或拿不到 buffer 时自动退到 **`new Audio()`（HTMLAudioElement）**，后者在 `file://` 下能出声。环境声在两条路径里都设了 `loop`。文件整体缺失时静默降级到 `ding()`。

## 四、本轮修的三件事（2026-11-14）

### 1. 静音时没有确认音 → 已修

原代码（第 1620–1628 行）先 `soundOn = !soundOn`，再 `sfx("ui_toggle")`，而 `sfx()` 第一行就是 `if (!soundOn) return;`。所以「开→关」是静音的。

改成两段式：**关之前**（仍在启用态）先响一次，**开之后**（已启用）再响一次。现在两个方向都有点击声。

### 2. 环境声 6 秒接缝 → 已换素材

旧 `ambience_studio.wav` 是原始未处理输出：288,000 帧 = 6.000 s @48 kHz，**没做任何淡出**，首样本 −199 / 末样本 −3，内容层面不连续。更麻烦的是电平不均——0.5 秒粒度 RMS 从 240 摆到 1950，循环一次就把这个起伏重复一次。

新素材的处理链：

| 步骤 | 做了什么 |
|---|---|
| 生成 | 重新生成 20.000 s 安静画室环境声（40 kHz / 立体声 / 16 bit，原始 RMS 仅 −35 dBFS） |
| 下混 | 立体声 → 单声道 |
| 重采样 | 40 kHz → 24 kHz（内容 95% 在 150 Hz 以下，24 kHz 的 12 kHz 奈奎斯特远高于内容带宽） |
| 电平对齐 | 增益 ×10.39，RMS 拉到 936（与旧素材一致，volume 0.18 的手感不变） |
| 循环处理 | 2 s 等功率（sin/cos）交叉淡化，20 s → **18.000 s** |

结果：432,000 帧 @24 kHz，864,044 字节；接缝跳变 40（−58.3 dBFS，实质连续）；RMS 864；峰值 4,529（−17 dBFS）；无削顶。每 2 秒 RMS 在 718–1063 之间，比旧版的 240–1950 平稳得多。

旧文件已留存为 `sfx\ambience_studio_6s_原版.wav`，想退回去把它改名成 `ambience_studio.wav` 即可。

**注意**：环境声现在是 24 kHz，其余 10 个音效是 48 kHz。WebAudio 会自动重采样，不需要改代码。

### 3. 换完之后发现的新问题：中高频塌了一半

换素材只解决了接缝，没解决"听感"。把两版按 150 Hz 分成低频/中高分带对比：

| 版本 | 时长 | RMS | 低频 <150 Hz | 中高频 >150 Hz |
|---|---|---|---|---|
| 原版 6 s | 6.00 s | 936 | 679 | **644** |
| 平稳 18 s | 18.00 s | 864 | 822 | **269** |

新版中高频只有旧版的 **42%**。也就是说同音量下它不是"更闷"，而是**更空**——旧版那 644 里装的是真实的纸页翻动和铅笔沙沙，新生成的素材是一条平稳的空调嗡鸣，没有事件。

试过用电平倾斜（`y = x + g·(x − lowpass₁₂₀(x))`）把中频补回来：g 从 1.0 试到 2.0，中高频只到 528（旧版的 78%），再往上补就是给噪声加增益，只会变"嘶"。**结论：这个缺口 EQ 补不回来，因为差的是内容不是频响。**

所以做了第三个候选 C（提亮版，g=2.0），并写了 `试听_环境声.html` 做 A/B/C 对比：

| 候选 | 文件 | 特点 |
|---|---|---|
| A | `sfx\ambience_studio_6s_原版.wav` | 有真实纸笔事件，但每 6 s 一次硬接缝 |
| B | `sfx\ambience_studio.wav`（**当前已装**） | 接缝 −58 dBFS，但中高频偏薄 |
| C | `sfx\ambience_studio_提亮候选.wav` | 中高频补到旧版 78%，可能偏嘶 |

选定后把对应文件改名成 `ambience_studio.wav` 覆盖即可，代码不用动。

**2026-11-14 结论：采用 B，代码不动。** 依据是分带能量实测（同一条音频的波段占比）：

| 频段 | A | B（采用） | C |
|---|---|---|---|
| 0–150 Hz | 53.9% | 92.8% | 68.6% |
| 150–500 Hz | 34.2% | 3.0% | 11.7% |
| 500–2000 Hz | 8.9% | 0.7% | 3.1% |
| 2000–5000 Hz | 2.2% | 1.8% | 8.4% |
| 5000–8000 Hz | 0.5% | 1.1% | 5.1% |
| ≥8 kHz | 0.2% | 0.6% | 3.0% |

理由：一轮 25 分钟，A 每 6 秒断一次 ≈ 250 次接缝，音质再好也不值得；C 的 ≥8 kHz 是 B 的 5 倍，而素材采样率只有 24 kHz（Nyquist 12 kHz），这一段能量多为插值产物，听感容易变成「底噪」，把「闷」换成「嘶」不算改善。

A / C 两个文件保留在 `sfx\` 里作备选，不删。三版连听音频在 `环境声_ABC连听.wav`（A 6 s → 静音 1 s → B 10 s → 静音 1 s → C 10 s，共 28 s），由 `make_abc_chain.py` 生成，量测脚本 `probe_bands.py`。若听完改主意，把对应文件改名成 `ambience_studio.wav` 即可，HTML 不需要改。

目标：用阶跃 StepAudio 3 的限免额度重生成一条「既有真实纸笔事件、又能无缝循环」的 20 秒环境声，把 B 的中高频缺口从内容层面补上。

三次结果（全部按 48 kHz **单声道**回传，不是立体声）：

|---|---|---|---|
| 1 | `ambience_studio_v2_raw.wav` | 5.775 s | 太短，循环重复感明显 |
| 2 | `ambience_paper_raw.wav` | 11.535 s | 每秒 RMS 从 1078 单调衰减到 6，等于"有结尾的场景"，不能循环 |
| 3 | `ambience_bed_raw.wav` | 10.415 s | 全段几乎安静（每秒 RMS 15–51），但峰值 32125（−0.17 dBFS），中间有一记爆点 |

### 5. 给自己发问号（新增能力）

原来「我的桌」渲染的是 `私有` 标签，没有 `?` 按钮；`sendQmark()` 只在 `demoPeers` / `remoteSeats` 里查 id，自己的 `MY_ID` 不在任何集合，直接 return——双封。

这么封是有道理的：这机制的原话是「系统先提醒一下，然后大家都可以发问号去压力他」，压力源是**同伴**。但同伴开关关掉时 `stepRoom()` 直接 return（第 764 行附近），没有任何同伴，补刀链路完全不存在——一个人自习时，这个 app 最核心的「被看见」机制是空转的。

所以加了这个能力，并按「不污染同伴压力数据」的方式实现：

| 改动 | 行 | 内容 |
|---|---|---|
| 计数变量 | 659 | `qSentSelf` / `qReceivedSelf` 独立于 `qSent` / `qReceived` |
| 渲染按钮 | 699 | 「我的桌」在 `私有` 之后再渲染一个 `.seat-btn.self`，虚线绿色，与别人的实线红色 `?` 区分 |
| 样式 | 236–240 | `.seat-btn.self` 虚线描边，hover 变实心 |
| 分发拦截 | 722 | `sendQmark()` 首行判断 `seatId === MY_ID`，转给 `sendQmarkSelf()` |
| 自助路径 | 737 | `sendQmarkSelf()` 不走 socket，直接本地调 `receiveQ(MY_NAME, MY_ID, true)` |
| 记录标记 | 743 | `receiveQ()` 增加第三参 `self`；记录里 `from` 记为「自己」，并带 `self: true` |
| 导出字段 | 1142–1143 | JSON 的 `room` 下新增 `qmark_sent_self` / `qmark_received_self`；`pressure` 数组每条本身已带 `self` |
| 文本摘要 | 1184 | 收到问号后面追加「（其中自助 n 个）」 |
| HUD | 1670 | 有自助记录时显示 `7（含自助 2）` |

**数据口径**：跨会话统计同伴压力时，按 `pressure.self` 过滤即可，`after_reminder_ms` / `reaction_ms` 对自助记录依然有效（自助问号同样会测你多久重新落笔），只是不能和同伴压力混算。

## 九、2026-11-14 新增：休息阶段（第三个真实功能改动）

### 1. 原来有什么问题

番茄钟到点后：`running=false`、状态写「本轮完成」、3.2 秒后 `setTimeout` 把它改回「未开始」，`remainMs` 停在 0。也就是说**没有休息这一段**——用户要么立刻重新点开始，要么关掉页面。`break_start.wav` 因此一直是死文件（FILES/VOLUME 都登记了，但没有调用点）。

### 2. 现在的状态机

```
idle ──开始自习──> run ──到点──> break（5 分；每第 4 轮 15 分）──倒计时归零──> idle
  ↑                                  └── 点「跳过休息」──> run（直接开下一轮）
  └── 重置（任何状态下都回到 idle，并把 breaking 清掉）
```

| 位置 | 行 | 做了什么 |
|---|---|---|
| 状态变量 | 648 | `let breaking = false, breakEnd = 0, breakTotalMs = 0` |
| `startBreak()` | 1268–1278 | 按 `stats.pomo % 4` 定 5 或 15 分；置 `breaking`、写 `breakEnd`；状态条「本轮完成 · 休息 N 分」；按钮改「跳过休息」；1.6 s 后响 `break_start` |

| `endBreakCue()` | 1290–1293 | 先 `stretch`（起身），0.9 s 后 `break_end`（回桌提示），后者要求此刻既不在自习也不在休息才响 |
| `startPomodoro()` | 1295–1308 | 从原点击回调里抽出来的开始逻辑，`跳过休息` 与 `开始自习` 共用 |

| 重置 | 1382 | 增加 `breaking = false` |

| 状态条样式 | 81 | 新增 `.status[data-s="break"]`（暖灰 #eeeae1 / 字 #6b6355），与 run / pause / done 都区分开 |

设计取舍：**休息不计入 `stats.focusSec`**（只有番茄到点那一刻加一轮时长），**休息期间不跑 `checkGuard()`**（久坐提醒只该在自习时催）。`stats.pomo` 仍然只在到点时 +1，所以「今日番茄」的数字口径没变。

### 2. 改了什么

| 文件 | 增益 | 倍数 | 源峰值 |

放大倍数按「目标有效峰值 -24 dBFS」反算，并断言放大后源峰值 < 0.95 FS 才写盘（三条都没削波），换算与写盘在 `sfx\normalize_sfx.py` 里，脚本本身幂等：已经在目标电平上就跳过。
