# 绘画自习室 · 桌面悬浮小窗 v0.7 —— 这次按原话做

> 结论先说：原话要的东西，网页做不出来。它要的是一个**浮在桌面上的小窗**，读**系统级指针**，
> 监测**你自己**在 Photoshop/Procreate 里画画。v0.4 / v0.5 / v0.6 全是「一个页面」，形态这一条就没对上。
> 这一版把它做成了真的桌面小窗，并且**没有**任何「几个人共用一张画布」的东西。

## 二、它到底怎么知道我在画画（不接软件）

```
每 33ms：
  GetCursorPos()              → 全局指针坐标（数位板笔尖在 Windows 里就是指针）
  GetAsyncKeyState(0x01)      → 左键(笔尖)按下，边沿=一次落笔
  GetAsyncKeyState(0x11) & (0x5A) → Ctrl 与 Z 同时按下，边沿=一次撤回
  GetForegroundWindow + QueryFullProcessImageNameW → 当前前台程序名
```

- **前台过滤**：只在 `photoshop.exe / painter.exe / clipstudiopaint.exe / krita.exe / sai2.exe / …`
  在前台时计数。你切去刷网页、聊微信，落笔不会被算进来（状态显示「不在绘画软件」）。
  `--anywhere` 可以关掉这条过滤。
- 白名单在 `DRAW_EXES`，觉得少了直接往集合里加一行，或先用 `--anywhere`。
- **完全不碰绘画软件本身**：不读工程文件、不读笔压、不装驱动、不要授权码。

度量口径：

| 指标 | 定义 | 备注 |
|---|---|---|
| 落笔 | 左键/笔尖按下边沿数 | 一笔算一笔，长线不重复计 |
| 撤回 | Ctrl+Z 按下边沿数 | 用别的方式撤销会漏计 |
| 每分钟 | 落笔数 ÷ 自习活跃分钟 | **分母是自习时长，不是从头到尾的墙钟**（沿用 v0.5 的修正） |
| 笔速 | 笔尖按下期间位移/dt 的指数平滑（px/s），另记峰值 | 抬笔移动不计 |

守护（和 v0.5/v0.6 同一套阈值，只是换了数据源）：

| 档 | 静默阈值 | 断崖比例 | 断崖持续 | 冷却 |
|---|---|---|---|---|
| 温柔 | 60s | 0.28 | 4s | 45s |
| 标准 | 20s | 0.35 | 3s | 30s |
| 严厉 | 10s | 0.50 | 2s | 15s |

断崖另加一条：峰值 < 300 px/s 不判崖（那是慢速细描，不是走神）。
提醒一次后**必须重新落笔**才重新武装，避免连续轰炸（这条在 v0.5 就有，v0.7 用 `pen_back()` 补 `delay_ms`）。

## 三、怎么跑

```
双击  小窗\启动小窗.bat          ← 找带 tkinter 的 Python（优先 3.12），用 pythonw 拉起来，无黑框
```

命令行参数：

| 参数 | 作用 |
|---|---|
| `--anywhere` | 不限于绘画软件前台，全局都计数 |
| `--demo` | 填演示数据（截图/讲解用），不读真实输入 |
| `--snapshot 路径.png` | 启动后自己抓一张窗口图再退出（PrintWindow，不需要屏幕截图权限） |
| `--selftest` | 跑核心逻辑 13 项自检，不开窗 |
| `--probe N` | 只读 N 秒真实指针，打印计数（自己验「到底有没有读到」最快的方式） |
| `--livetest` | 在自家窗口里合成一次按下—拖动—抬起，验证 Win32 链路通了没 |
| `--export-test` | 起窗后立刻导出一次 JSON 再退出 |

小窗操作：拖标题条移动 · `—` 收成小条 · `✕` 退出 · Esc 退出 · 点档位切阈值 · 点「？」给同桌施压 · 「守护」开关本轮提醒 · 「导出数据」写 JSON。

## 四、数据出口（schema 3）

文件名 `自习室_<档>_<社交条件>_<时间戳>.json`，落在 `小窗\导出\`：

```
schema_version 3
source      {input:"windows global pointer + Ctrl+Z", foreground_filter, draw_apps[], sample_hz}
session     {started_at, ended_at, active_sec, condition, social_condition, planned_min}
desk        {stroke_count, undo_count, path_px, pen_down_sec, avg_speed_px_s,
             peak_speed_px_s, current_speed_px_s, strokes_per_min}
guard       {enabled, level, thresholds{...}, reminder_count, reminders[{signal, at, delay_ms, exe}]}
room        {code:"302", peers_enabled, demo_peers:true, peer_states[], qmark_sent, qmark_received,
             pressure[{at, from, after_reminder_ms, reaction_ms}]}
pomodoro    {rounds_completed, focus_sec}
data_valid  （落笔 > 0 才 true，缺数据不写假数）
limits[]    （五条结构性限制，原样进文件，答辩时直接引用）
```

`delay_ms`＝被提醒到重新落笔之间隔；`reaction_ms`＝收到同伴问号到重新落笔之间隔。这两个数就是
「轻微社交压力到底有没有用」的唯一硬证据，别用问卷代替。

## 五、这次验了什么（都是本机实测，不是估的）

1. `--selftest` **13/13 PASS**：落笔计数、路径/笔速、按住 Ctrl+Z 不重复计、非绘画软件不计数、
   静默触发且不重复轰炸、重新落笔补 `delay_ms` 并重置武装、断崖触发且带峰值、每分钟口径。

4. 常驻 7 秒不崩（`pythonw` 进程存活）。
5. `启动小窗.bat` 实测拉起进程（pid 23136）。
6. 导出 JSON：`自习室_standard_with_peers_20261113_212140.json`，2804 B，`json.load` 通过，schema 3，11 个顶层键。

## 六、没验的（别当已验证）

1. **真实数位板在 Photoshop 里的落笔是否等同于左键**——这是整套方案的地基，只能你本人拿笔画一次才算数。
   验法：开小窗 → `python 小窗\paint_studio_widget.py --probe 20` → 在 PS 里画十笔 → 看 `strokes` 涨不涨。
2. **撤回快捷键**：PS 是 Ctrl+Z，Procreate 在 iPad 上根本不在这套 Win32 里；SAI/Clip Studio 自定义快捷键会漏计。
3. 笔压/倾角/笔触：原话提到「笔触之类的」，但读全局指针拿不到压力值，本版**不做**，别写进报告当功能。
4. **同桌仍是本机演示**（`demo_peers: true`）。真实联机需要后端，和 v0.6 是同一个坑，没解决。
5. 多显示器/高 DPI：坐标是物理像素，跨屏移动时 `path_px` 会跳；截图与窗口定位在 125% 缩放下未逐档校准。
6. 「直接读鼠标」= 任何左键拖动都像落笔；靠前台白名单挡掉浏览器/聊天，但如果绘画软件里点菜单，也会被记一笔。
7. 权限：普通用户即可（不读别的进程内容，只读进程名）。没测过 UAC 提权程序在前台时的行为。

## 七、和 v0.6 的关系

- **v0.7（本文件）＝原话的形态**：桌面小窗，读系统指针，监测你自己。答辩时这才是「原型」。
- **v0.6（网页版）＝房间视图**：它证明的是「一房多座、私有桌、只同步状态与问号」这套社交结构，
  页内画布只是为了把状态跑起来。**不能拿它当形态证据**——它恰恰是原话里被否掉的那句「一个这样的页面」。
- 两者共用的东西：档位阈值、两段社交压力（系统提醒 → 同伴问号）、schema 字段命名、`ppm` 分母口径。
- v0.5 及其共绘协议已彻底作废，不再引用。

桌面版是「一人一格」的客户端，适合**一对一现场试用**：让对方在自己电脑上双击 `启动小窗.bat`，
在自己常用的绘画软件里画 3 分钟，看三件事——

1. 落笔/撤回数准不准（准不准＝能不能替代人工观察，这是 RQ 的地基）；

3. 同伴问号来了，他下一笔隔多久（`pressure.reaction_ms`）。

房间多人那一段仍用 v0.6 的网页跑，别在首场同时上两套。招 4 个人这件事没动，0/4。
