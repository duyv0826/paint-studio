# 标定流程（半天，6 个人）

目标：把原型里那三档"设计取值"换成有出处的数，口径写成 **n=6 初步标定**，不写成"实验验证"。

## 文件

| 文件 | 干什么 |
|---|---|
| `笔速标定采集页.html` | 单人采集：双击打开，填编号，画满设定时长，自动导出 JSON |
| `标定_分位分析.mjs` | 把一批 JSON 合并，算出分位并给出三档建议值；`--write` 同时写一份 `建议_三档阈值.md` |
| `README_标定流程.md` | 本文件 |

## 步骤

1. **准备**：把 `笔速标定采集页.html` 发给 6 个人（单文件，双击即可，不需要装东西、不需要服务器）。
2. **每人一段**：填 `S01`…`S06`，点「开始」，然后**随便画 20 分钟**。告诉他们：
   - 中途停手、看手机、发呆都可以，停手本身就记；
   - 一段里至少出现 3 次「停 1 分钟以上」、2 次「明显画慢/犹豫」——不然断崖比例没分布可算。
3. **收文件**：每人结束时会自动下载 `标定_S0x_日期_时间.json`。全部丢进同一个文件夹（建议 `标定/导出/`）。
4. **算**：在本目录执行
   ```
   node 标定_分位分析.mjs "标定/导出" --write
   ```
   终端会打印逐人指标 + 合并分位 + 一段可直接替换的 `LEVEL_PROFILES`；`建议_三档阈值.md` 是给论文/答辩用的那一版。
5. **回填**：把建议值替换进 `绘画自习室_单文件原型_v0.7_*.html` 的 `LEVEL_PROFILES`，同时把页面里"设计取值，非实测标定"改成"**n=6 初步标定（2026-11-xx）**"，方法一节写明采样方式。
6. **`--demo` 是什么**：只用来验证脚本本身跑得通，产出的是合成数据，**不要当标定值用**。

## 算法（采什么、怎么算）

- 采样 **4 Hz**（每 250 ms 记一个笔速点），画布固定 **900×600 CSS 像素**，导出的是逻辑坐标下的 px/s。
- 笔速 = 指针位移 / 时间，做 EMA 平滑（旧值 0.72 + 新值 0.28）；停手 180 ms 后以 ×0.86 逐步衰减。
- 单帧瞬速**上限钳制 3000 px/s**。没有这道钳制时，一次掉帧或合成事件（dt 小到 1 ms、位移几百 px）能算出几万 px/s 的假峰值，进而把 20 s 滚动峰值抬高、让"掉落比例"系统性偏低。这个漏洞在试跑时实测到过（38367 px/s），加钳制后同一次动作最高 844。
- 停笔段 = 相邻两次移动间隔 ≥ 1.2 s，记时长进 `idle_gaps_sec`。

## 三条容易踩的坑

1. **画布必须 900×600 CSS 像素，别缩放窗口。** px/s 是像素单位，画布一变，数字就不可比。脚本检测到画布不一致会打警告，但那时已经白采了。
2. **别混设备。** 同一个人在触控板、数位板、不同 DPI 的屏上画，笔速量级差很多。6 个人请统一一台机器（或至少记录并按设备分组算）。
3. **场景要对得上。** 自由画 20 分钟，停笔天然很长（自检里 p50 就能到 100 s）；而"自习中画一张草稿"的停笔会短得多。标定时请让被试按**接近真实使用的状态**画（例如画一张速写或临摹），否则算出来的阈值会宽得没法用，还得在方法里解释这一层差异。

## 产出怎么用才不心虚

写完数字之后，页面/论文里配这一句，比任何形容词都值钱：

> 三档阈值取自 6 人自由绘画的笔速与停笔分布（p25/p50/p75 分位），为**初步标定**；样本量不足，不构成实验验证。

n 小不是问题，把 n 说清楚才是。反过来，拿 n=6 去说"经实验验证"，是这次"去妆"最想避免的那件事。
